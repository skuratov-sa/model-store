## Реализация и режимы

- Добавлен один переходный пакет `bridge/dictionary`. Он не пишет в таблицы. При флаге `modern` `Flux.defer` откладывает вызов `DictionaryQuery` до подписки, `subscribeOn(Schedulers.boundedElastic())` уводит JDBC с WebFlux event loop. `DictionaryQuery.findByType` уже имеет `@Transactional(transactionManager = "transactionManager", readOnly = true)`; транзакция начинается и заканчивается на том же worker. Legacy делегирование не меняет цепочку R2DBC.
- Для `PRODUCT_AVAILABILITY` use case вызывается с `isAdmin=true`, чтобы сохранить текущую фильтрацию в `DictionaryController` по `JwtService`: гость/USER видит две записи, ADMIN все записи. Другие enum и порядок читаются существующим JDBC запросом без искусственного JPA ID.
- MVC-контроллеры modern имеют профиль `modern`; в legacy остаются старые контроллеры. `LegacyRuntimeConfiguration` содержит `@EnableScheduling` только при `!modern`; новых планировщиков не включено. Принятый ранее `CategoryServiceBridge` не расширен. Ранее его `category=modern` технически включался несмотря на смешанную запись; теперь legacy startup явно отклоняет эту настройку с причиной. Modern профиль guard не регистрирует. Это **не** переключатель, принятый пунктом 19.
- Для отдельного переключения `/categories`, адреса или только чтения изображений без влияния на соседние интерфейсные вызовы понадобился бы минимальный точечный hook в соответствующем старом контроллере (`CategoryController.java`, `AddressController.java`, `ImageController.java`) либо явная маршрутизация на HTTP-слое. Эти Java-файлы не менялись, поскольку точечная передача координатором не получена; независимый `/dictionary` выполнен без hook.

## Проверки и ограничения

Тестовые контексты используют собственную embedded PostgreSQL, `@MockitoBean` для S3/SMTP и `app.private-key-path=keys/test_private_key.pem`; рабочие сервисы и почта не вызываются. Новые проверки: default и явный `legacy`, `modern` на единственном объявленном переключаемом маршруте, HTTP для гостя/USER/ADMIN, неизвестный enum, соседний `/categories`, присутствие старых scheduler, отсутствие modern MVC контроллера в legacy, отложенный вызов, `boundedElastic` и активная JPA транзакция на JDBC-порту. Откат записи для этого адаптера неприменим: он только читает; транзакции записи соседних сценариев не переключались.

`compileTestKotlin --offline --no-daemon` прошёл. При первом запуске старые modern-контексты без настроек ключей не поднялись; повторный запуск с тестовыми `app.private-key-path` и `app.public-key-path` прошёл. Это не изменение production-конфигурации.

## Самостоятельная проверка после реализации

- Повторно сверены все production-упоминания `DictionaryService`: инъекция интерфейса есть только в старом `DictionaryController`; `DictionaryServiceImpl` внедрён непосредственно только в новый bridge. Bridge имеет `@Profile("!modern")`, а modern HTTP тест поднимает MVC без конфликта бинов. Для будущего нового потребителя интерфейса этот `@Primary` потребуется пересмотреть.
- Проверено, что при пустом и явном `LEGACY` используется старый `DictionaryServiceImpl` и modern use case не вызывается. При `MODERN` вызов откладывается до подписки; ошибка JDBC доходит подписчику без legacy fallback. Nullable `value` и `description` сохраняются при отражённом вызове Lombok all-args конструктора. Имена всех старых/новых enum совпадают в существующем HTTP тесте.
- Проверено, что `PRODUCT_AVAILABILITY` остаётся отфильтрованным старым контроллером для гостя/USER и полным для ADMIN. Путь ошибки неизвестного `type` остаётся HTTP 400. Современный JDBC порт наблюдался на `boundedElastic-*` с активной транзакцией; `DictionaryQuery.findByType` явно выбирает `transactionManager` JPA. `Flux.defer` и `subscribeOn` сохраняют стандартную отмену подписки Reactor; уже начавшийся блокирующий JDBC запрос не прерывается гарантированно отменой HTTP запроса, но новых записей и внешних действий у этого чтения нет.
- Сверены `ModernModeLegacyFilter`, профили MVC-контроллеров и legacy `@EnableScheduling`; тест подтверждает отсутствие modern контроллера справочника в legacy и наличие всех трёх старых scheduler. Исправлена неточная строка аудита: старый заказ вызывает у `BasketService` именно `removeFromBasket`, а не чтение корзины. Добавлены маршруты auth и агента в таблицу.
- Выборочный запуск до startup guard на отдельной embedded PostgreSQL: **17 тестов, 0 ошибок**, затем `bootJar` — успешно. В test worker видны оба параметра `JAVA_TOOL_OPTIONS` для тестовых ключей; S3 и SMTP заменены mock.

После самостоятельной проверки координатор указал, что одной документации о небезопасном `category=modern` недостаточно. Добавлен отдельный `LegacyScenarioSafetyGuard` в переходном пакете: legacy context не запускается с этим флагом и выдаёт ясную ошибку; default/явный `category=legacy`, `dictionary=modern` и modern профиль проходят. Старый `CategoryServiceBridge`, catalog/domain и Java-код не менялись. Неполные тесты nullable значений и передачи ошибки, а также неточности таблицы исправлены ранее. На обновлённой локальной базе `4a40933`: **24 теста, 0 ошибок**, `bootJar` собран. Проверены оба режима, ранее существовавший прямой тест CategoryServiceBridge, новый startup guard и HTTP справочника. Оставшиеся ограничения — смешанная запись избранного/корзины и невозможность гарантированно прервать уже начавшийся JDBC read при отмене HTTP. Принятая 12.1 вошла в базу и больше не числится ограничением пункта 19.
