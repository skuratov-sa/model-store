## Отдельное самостоятельное ревью 20.10.2026

- Исправлено: проверка ADMIN и запрет `agent_access` находились только в MVC контроллере, а прямой вызов application мог получить историю или изменить собственный розыгрыш с ролью USER. Все use case теперь принимают `GiveawayCaller` со скалярами проверенного Actor и повторно проверяют роль, ID и тип токена. Прямые вызовы USER/agent_access покрыты тестом.
- Исправлено: прежний modern `PUT /product/{id}` отклонял собственный GIVEAWAY даже для ADMIN. Узкая маршрутизация в переданном `ProductCommandController.kt` сохраняет обычный CRUD; новый `UpdateGiveawayProduct` обрабатывает редактирование полей, настроек и переходы в/из GIVEAWAY с обязательной проверкой владельца, активных заказов, URL, победителей, дат и пересечения периодов. Транзакция охватывает поля товара, настройки, категории и привязку изображений. Тест проверяет откат поздней ошибки категории после изменения настроек и claim фотографии.
- Проверено: после V1.28 нет глобального unique index; две соседние непересекающиеся включённые даты допустимы, перекрытие блокируется под `dictionary → product` lock. Конкурирующие создания, обновления и смена статуса не оставляют включённый заблокированный розыгрыш. Конверсия обычного товара и резервирование16.1 сериализуются на строке product без взаимной блокировки. Один товар за вызов исключает разнонаправленный порядок product ID; media claim использует принятый owner port.
- Реальный legacy/modern HTTP подтвердил одинаковые успешные ответы, имена полей/null, сообщения и коды на проверенных товарных и административных путях. Намеренные отличия безопасности для 32: подписанный `verify` JWT проходит legacy административное чтение (200), modern отклоняет (401); подписанный `agent_access` с `issuedBy=admin` проходит legacy (200), modern возвращает 403. Поддельный, просроченный и refresh JWT отклоняются обоими режимами. Текст ошибки БД modern не раскрывает в `details`; legacy общий обработчик может возвращать `dbMessage`.
