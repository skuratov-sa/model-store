# Способы передачи (пункт 09)

`GET/POST /transfer`, `PUT/DELETE /transfer/{id}` используют ID участника из проверенного `Actor`. `GET` показывает только `ACTIVE` и отвечает прежним `404 TRANSFER_NOT_FOUND`, если список пуст. `DELETE` переводит собственную запись в `DELETED` и допускает повторное удаление. Создание одного и того же активного `sending` отвечает прежним `409 TRANSFER_NOT_FOUND`; строка участника блокируется на время проверки и вставки.

Для пункта 32: legacy HTTP enum `Currency` содержит `CREATE`, но PostgreSQL enum `currency` — нет. Modern распознаёт это значение и возвращает `400 BAD_REQUEST` до записи вместо прежней ошибки БД. Modern также возвращает `400 BAD_REQUEST` при отсутствии обязательных `sending`, `price` или `currency`; legacy передавал такие значения в БД. Изменение `sending` при `PUT` по прежнему не проверяет уникальность: это соответствует legacy, но позволяет получить повторяющиеся типы после обновления. Порядок строк в `GET` не задан ни одним контрактом.

Административные `/admin/actions/agents/{agentId}/transfers` принадлежат пункту 29.2 и сюда не входят. В legacy-режиме работают прежние Java-контроллер и сервис.
