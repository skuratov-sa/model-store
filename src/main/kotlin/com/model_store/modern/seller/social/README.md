# Социальные сети (пункт 09)

`GET/POST /social-networks`, `PUT/DELETE /social-networks/{id}` используют ID участника из проверенного `Actor`. Пустой список даёт прежний `404 SOCIAL_NETWORK_NOT_FOUND`; повторный `type` при создании — `409 SOCIAL_NETWORK_ALREADY_EXISTS`. `DELETE` физически удаляет только собственную запись. Строка участника блокируется на время проверки типа и вставки.

Для пункта 32: modern возвращает `400 BAD_REQUEST` для отсутствующего `type` и `login` длиннее 255 символов до записи; legacy доводил такие значения до ошибки БД. Изменение `type` при `PUT` по прежнему не проверяет уникальность, как и legacy. Порядок строк в `GET` не задан.

Административные `/admin/actions/agents/{agentId}/social-networks` принадлежат пункту 29.2 и сюда не входят. В legacy-режиме работают прежние Java-контроллер и сервис.
